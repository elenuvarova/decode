# Decode — Knowledge Base + RAG (законодательная база)

**Фаза:** Product/Tech · **Дата:** 2026-08-02 · **Входы:** [research/08-tech-rag-backend.md](../../research/08-tech-rag-backend.md), [defensibility.md](defensibility.md)

«Скормить законодательную базу через RAG, чтобы работало лучше?» — да, но с дисциплиной. **RAG не даёт правильность, он даёт grounding-ретрив по большому меняющемуся корпусу.** Помогает в одних слоях, вредит в других.

## 1. Где RAG НЕ нужен
**Сам документ юзера** (T&C, renewal-письмо) — несколько страниц, влезает в контекст. **Full-context чтение надёжнее чанков.** RAG-ить один короткий договор — оверинжиниринг.

## 2. Где законодательная база через RAG помогает
Корпус UK-регуляторики **большой и меняющийся** (Consumer Credit Act 1974, Consumer Rights Act 2015, **DMCC Act 2024**, FCA CONC/Handbook, правила CRA, **BNPL-регуляция 2026**). В контекст не влезет, устаревает → RAG держит его свежим и цитируемым.

## 3. Критическое различие (иначе — красиво-неверно)
| Слой | Как делаем | Почему |
|---|---|---|
| **Определения** (trap-каталог, credit-file YES/NO, true-cost) | **курируемые верифицированные decision-таблицы / правила** — детерминированно, аудируемо, НЕ raw-RAG по закону | «идёт ли ЭТОТ Pay-in-3 в credit file?» нельзя надёжно вывести, зарэгав статут — модель сделает неверный прыжок |
| **Обоснование / объяснение** | **RAG по закону** — подтянуть и **процитировать** пассаж, объяснить простым языком | provenance + «что термин вообще значит»; грузонесущее определение — в курируемом слое |

**Пример (Klarna Pay-in-3):**
- Determination (курируемые правила): «Pay-in-3 → сейчас не регулируемое кредит-соглашение → не передаётся в CRA → **credit-file: NO**; late fee £X по текущим условиям».
- Юзер тапает «почему?» → RAG достаёт и цитирует основание (`currently exempt · не шарится с CRA на дату X`) + ссылка.

## 4. Комплаенс-мина
RAG-по-закону, синтезирующий **«вот твоя юридическая позиция / тебе стоит…»** = дрейф в регулируемый фин/юр-совет (FCA). Поэтому RAG строго ограничен: (а) grounding/цитата курируемых определений, (б) «что термин *в общем* значит» — и **никогда** case-specific совет / «тебе стоит».

## 5. Архитектура (Phase 2, из research/08)
- **pgvector в Supabase** + **гибридный поиск** (BM25 + вектор, RRF-фьюжн).
- Два юзкейса: (1) **регуляторный KB** (grounding/цитаты), (2) **cross-vault Q&A** («по всем моим документам — что висит?»).
- **Single-doc decode остаётся full-context** (не RAG).
- Источник корпуса: legislation.gov.uk API (build-time) + курируемые decision-таблицы (см. [integrations.md](integrations.md)).

## 6. Net
«Скормить базу» стоит — но как **курируемый + RAG-заземлённый knowledge-слой с guardrails**, где грузонесущая логика (определения, математика) остаётся детерминированной/курируемой. Это прямо усиливает ров: RAG даёт свежесть и провенанс, **курирование даёт правильность** — того и другого нет ни у generic-LLM, ни у трекеров.
