# Reusable research-промпты — advanced T2/T4/T5

Переиспользуемые prompt-шаблоны («продвинутый уровень» задач курса): генерация персон (T4), кодирование интервью и VoC-разметка (T2/T5). Заполнить {плейсхолдеры} и запускать в Claude/Gemini.

## 1. Persona-generation (T4)

Сгенерировать/обновить грань сегмента как воспроизводимую карточку. Использовался для 4 персон в [task4-personas-premortem.md](../task4-personas-premortem.md).

> Ты строишь evidence-based AI-персону для симуляции, НЕ маркетинговую персону. Продукт: Decode (AI-декодер фин-документов, UK, BNPL 18–25).
>
> **Источник истины (только это, не выдумывай):** {вставить релевантные verbatim-цитаты и кластеры болей из research/11 + JTBD jobs}.
>
> Построй персону-грань сегмента по схеме:
> - Имя, возраст, город, занятость, кэшфлоу
> - Поведение с BNPL (сколько планов, как платит, читает ли условия)
> - Уровень фин-грамотности и копинг-стиль (избегание/контроль/тревога)
> - Job-ядро (какие из J1–J6 для неё главные)
> - Цитата-якорь (verbatim из источника, не перефразируй)
> - «Что её уволит из продукта» (триггеры отказа)
> - Назначение в симуляции (какую грань/риск она проверяет)
>
> Требование: персона должна **отличаться** от уже существующих {перечислить}, а не быть их усреднением. Если данных на грань не хватает — скажи прямо, не достраивай фантазией.

**Симуляция прогона по loop** (отдельный вызов на персону):
> Ты — {персона, вставить карточку}. Тебя проводят по приложению Decode шаг за шагом: {вставить шаги core loop / CJM}. На КАЖДОМ шаге ответь от первого лица: что думаешь, что чувствуешь, что делаешь дальше, и честно — на каком шаге бы засомневался или бросил и почему. Не подыгрывай продукту; если что-то раздражает или непонятно — говори. В конце оцени риск отвала на каждом шаге 🔴/🟡/🟢.

## 2. Interview coding / VoC labeling (T2 + T5)

Единый шаблон разметки — для транскриптов интервью (T2) и для отзывов (T5, свои или конкурентов). Аналог «Sheets → Gemini auto-coding» курса.

> Ты — research-аналитик. Размечаешь {транскрипт интервью / массив отзывов} для продукта Decode (UK, BNPL 18–25).
>
> Извлеки каждую отдельную единицу (эпизод для интервью = реальное прошлое событие; для отзыва = одна жалоба/похвала). Для каждой заполни:
> ```
> | id | unit_text (verbatim) | theme | job (J1–J6 или none) |
>   hypothesis (H1–H5 или none) | sentiment (-2..+2) |
>   severity (вред job: low/med/high) | trust_impact (yes/no) |
>   signal (confirms/refutes/nuance) | our_requirement |
> ```
> Правила:
> - Цитаты — **verbatim**, не пересказ.
> - Для интервью: гипотетические высказывания («я бы…») помечай `unit_type=opinion`, НЕ используй для signal.
> - theme: для VoC используй фикс-список T-1…T-7 ([task5](../task5-voc-action-points.md)); для интервью выделяй индуктивно.
> - Не выдумывай связь с job/hypothesis — если её нет, ставь `none`.
> - В конце: агрегат по theme и по hypothesis (сколько confirms/refutes/nuance), и 5 самых сильных verbatim-цитат.
>
> Затем человек проверяет 20% строк вручную; при расхождении >15% — правим определения и перезапускаем (auto-coding ускоряет, но не заменяет валидацию).

**Схема определений** (вставлять в промпт, чтобы маппинг был стабильным):
- J1–J6 — из [jtbd.md](../../product/jtbd.md) §2
- H1–H5 — из [jtbd.md](../../product/jtbd.md) §7
- T-1…T-7 — из [task5-voc-action-points.md](../task5-voc-action-points.md) §1

## 3. Принцип (посыл курса)

Все три промпта — ускорители, не авто-пилоты: персоны проверяются интервью, разметка — человеком на выборке, UX-ревью — реальной юзабилити. «AI убирает рутину, но не заменяет исследователя» — поэтому каждый шаблон содержит явный gate валидации человеком.
