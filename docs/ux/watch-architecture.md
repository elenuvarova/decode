# Decode — архитектура Watch (Vault + Renewal Radar)

**Фаза:** UX/Product · **Дата:** 2026-08-02 · **Входы:** core loop (Scan→Understand→Decide→Watch), [research/33](../../research/33-scope-and-input-strategy.md), конкурентный ресёрч ([research/references/competitors-by-logic.md](../../research/references/competitors-by-logic.md), [refero-scan.md](../../research/references/refero-scan.md))

Watch — retention-движок Decode и мост к монетизации (сегмент S2 renewal payers).

## 1. Единица Watch — «Commitment»
Не «подписка» и не «транзакция», а **обязательство с будущими датами**, порождённое сканом:
```
Commitment {
  источник: документ + citations
  тип: BNPL | подписка | страховка | контракт
  расписание: [{сумма, дата}]        // напр. Pay-in-3: £68.67 × 14 Jun/Jul/Aug
  trap-флаги: [...]
  credit_file: YES | NO | COND
  канал_отмены: телефон/URL (signpost, не совет)
  статус: см. §4
}
```
Принцип из ресёрча: **Radar = следствие скана**, не standalone (урок Little Birdie). Ручной Add-Commitment есть, но вторичен.

## 2. Движок напоминаний — наш дифференциатор (детерминированные локальные пуши)
Дедлайн берётся **из документа**, а не из банковских транзакций → напоминания планируются заранее:
1. При decode извлекаем будущие обязательства.
2. На экране **Save & Watch** показываем расписание — юзер **подтверждает/правит** (не планируем вслепую; страхует от ошибок извлечения).
3. Регистрируем **локальные нотификации** на `дедлайн − lead-time`. Payload = дата + сумма + **последствие пропуска** + спокойное действие.
4. Срабатывают **на устройстве, офлайн, без сервера и без банка** (`UNUserNotificationCenter` / на стеке Expo — `expo-notifications`).

**Почему это просто:** дедлайн детерминирован (фиксированная календарная дата) → в реальном времени сторожить нечего, просто заранее запланировали. Отсутствие bank-link — **причина надёжности**, не костыль.

### Реализуемость и ограничения
| Ограничение | Обход |
|---|---|
| iOS-лимит **64 pending** нотификации/приложение | **скользящее окно**: планируем ближайшие N, до-планируем при открытии / через background-refresh / опц. silent push (APNs, не банк) |
| нужно разрешение на пуши | primer-экран + деградация: in-app Overview/Calendar + опц. email |
| **не знаем, оплатил ли юзер** (нет банка) | кнопка **«Handled/Paid»** отменяет пуш; формулировка heads-up «due ~28 Jun», не «ты должен» |
| ошибка извлечения даты/суммы | шаг подтверждения расписания + citations на источник |

Мы точны по **дедлайну**, но не по **статусу оплаты** — единственный честный trade-off, закрывается кнопкой «Handled».

## 3. Четыре поверхности (существующие экраны) и связи
1. **Overview (кокпит)** — «что предстоит + что требует внимания». Группировка **по срочности, не по типу**: сводка-overlap (committed · due 7д/30д/60д = «£500 в этом месяце») → `Needs attention` → `Renewing soon` → `Active` + trap-баннер.
2. **Vault (список)** — все коммитменты, фильтры (Renewing/BNPL/Credit-file), поиск.
3. **Vault-Detail (один коммитмент)** — паттерны из Subo: 3-колоночная стат-полоса (Total | Next | Credit-file) + key-terms с citations + notes + **двухуровневые действия** (обратимое «Stop watching» ≠ «Delete»; «Edit reminders»; signpost-канал отмены). Как Fabric — таб **Ask** прямо на документе.
4. **Время:** **Payment-Calendar** (суммы на датах + футер-тоталы, как Rocket Money «Coming Up») · **Alerts-Inbox** (сработавшие) · **Radar-Settings** (lead-times, quiet hours).

## 4. Жизненный цикл
`Active → Renewing soon → Due → Overdue → Handled/Paid → Cancelled/Archived`.
Статус меняет группировку в Overview и каденс напоминаний.

## 5. Рамки (обязательные)
- **FCA:** факт + последствие + **канал** отмены, но не «тебе стоит отменить/переключиться».
- **Без bank-link на входе** → дедлайны детерминированы → локальные пуши.
- **Тон** безоценочный.
- **Монетизация:** free следит за N коммитментов; **Pro** = безлимит + price-creep-алерты + более ранние lead-time (прогрессивное доверие, не dark). Это же переход на S2.

## 6. Зафиксированные развилки
| Развилка | Решение |
|---|---|
| Overview: срочность / время / тип | **По срочности** + Calendar как второе (временное) представление |
| Напоминания: фикс / настраиваемые | **Настраиваемые**, дефолт 3д + day-of |
| Вход в Watch: только скан / + ручной | **Scan-first**, ручной вторичен |

**Суть:** скан рождает коммитмент → коммитмент живёт в Radar на детерминированных локальных напоминаниях. Пересечение decode × Watch без bank-link не даёт ни LLM, ни трекеры.
