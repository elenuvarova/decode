# Разбор метрик wireframe-кита «example3» (job-search app)

**Что это:** импортированный в наш Figma-файл (`ZR4wMSgGSbdckASvpiFwIP`) сторонний UI-кит мобильного приложения для поиска работы (canvas `example3`, node `694:20225`). 236 экранов формата iPhone + секция `wf-atoms` (иконки, сепараторы, прогресс-бары, теги). **Не Decode** — это внешний референс. Ниже — реверс его измерительной системы (отступы / размеры / шрифты / радиусы) и сверка с нашей DS.

**Как снято:** `get_design_context` по двум репрезентативным экранам — `428_AI Career Hub` (дашборд: навбар, hero, поиск, список-меню, таб-бар) и `428_Login` (соц-кнопки, инпуты, чекбокс, CTA). Кит **токенизирован** — значения приезжают как переменные (`--indent/*`, `--blocks/inside/*`, `--round/*`, `--colour/*`), плюс именованные текст-стили `wf/*`.

| Параметр | Значение |
|---|---|

| Ширина контента | **396px** |
| Боковые поля | **16px** ( (428−396)/2 ) — совпадает с нашим screen-padding |
| Status bar | 47px (реальный SF Pro Text 17, ls −0.408) |
| Nav-строка (Left·Title·Right) | высота 42px, px 16, py 8 |
| Bottom tab bar | высота 83px, home-indicator 5×134, blur 10px, верхний хайрлайн `0 −0.5px rgba(0,0,0,.3)` |

## 2. Спейсинг — ДВЕ параллельные шкалы (главная проблема кита)

Кит держит **два разных набора токенов для одного и того же** — отступы между блоками (`indent/*`) и внутренние паддинги (`blocks/inside/*`). Значения пересекаются и конфликтуют по именам:

| `indent/*` (гэпы/маржины) | px | | `blocks/inside/*` (паддинги) | px |
|---|---|---|---|---|
| xsss | **5** ⚠️ off-grid | | xss | 8 |
| xs | 8 | | xs | **16** |
| s | 16 | | m | 32 |
| m | 24 | | | |
| l | 32 | | | |
| xl | 48 | | | |
| xxl | **80** | | | |

⚠️ **Коллизия имён:** `indent/xs = 8`, но `blocks/inside/xs = 16`. Один и тот же суффикс «xs» = разные значения в двух шкалах → ловушка при сборке. `indent/xsss = 5` выпадает из 4/8-сетки.

**Наблюдаемые гэпы в композиции:**
- Между крупными блоками главной — 32 (`indent/l`)
- Между навбаром-hero и строкой поиска — 80 (`indent/xxl`) — очень воздушно
- Заголовок ↔ подпись в hero — 8
- Форма логина: 48 между формой и CTA, 24 между группами, 16 между полями
- Сепаратор «or»: гэп 20px

## 3. Высоты контролов — единый ритм 60px (сильная сторона)

| Контрол | Высота | Радиус | Паддинг |
|---|---|---|---|
| Поле поиска | 60 | 12 (`round/s`) | px 16 |
| Инпут (email/пароль) | 60 | 12 | px 16, py 8 |
| Пункт списка-меню (Dropdown) | 60 | 12 | px 16 |
| Соц-кнопка (Apple/Google) | 60 | **15** (`rounding/m`) | py 16, border 2px |
| Primary CTA «Log in» | 60 (min=max lock) | 12 | px 16 |
| Карточка «Image and video» | 230 | 16 (`round/m`) | 32 |

Все интерактивные элементы = **60px** → комфортный тач-таргет (>44 минимума), консистентно. Хорошо.

## 4. Радиусы — рассинхрон

| Токен | px | Где |
|---|---|---|
| `round/xss` | 4 | чекбокс |
| `indent/xsss` (как радиус) | **5** ⚠️ | контейнер инпута |
| `round/s` | 12 | инпуты, поиск, список, CTA |
| `rounding/m` | **15** ⚠️ | соц-кнопки |
| `round/m` | 16 | карточка |

⚠️ **Два «m»-радиуса** (`round/m=16` и `rounding/m=15`) из разных семейств живут одновременно; плюс 5px-радиус тянется из спейсинг-токена. Пять радиусов 4/5/12/15/16 без единой лестницы — визуально соседние 12/15/16 почти неотличимы, но токены разные.

## 5. Штрихи и цвета

**Stroke:** `stroke/s = 1`, `stroke/l = 2`, `stroke/weight/s = 1.5` (снова два семейства для толщины).

**Палитра (грейскейл-вайрфрейм):**
| Токен | Значение |
|---|---|
| `colour/light` / `colour/background` | white |
| `colour/dark` / `colour/accent-dark` | black |
| `colour/grey` | #dadada (бордеры, дизейбл-текст) |
| `colour/dark-grey` | #6c6c6c (вторичный текст, таб-иконки) |
| `colour/medium-grey` | #f0eeee (плейсхолдер-карточка, таб-бар) |

## 6. Типографика (`wf/*`, шрифт Inter)

| Стиль | Шрифт | Размер | Line-height | Где |
|---|---|---|---|---|
| `wf/H3` | Inter Bold | **32** | 1.15 | hero-заголовок |
| `wf/button big` / `wf/button tertiary` | Inter Bold | **18** | 1.15 | CTA, ссылки |
| `Ui-wf/Buttons` | Inter Medium | 18 | 1.15 | лейблы инпутов |
| `wf/body bold` | Inter Bold | **16** | 1.5 | пункты меню, title навбара |
| `wf/body` | Inter Regular | 16 | 1.5 | body/линки |
| `Ui-wf/Body text` | Inter Regular | 16 | **1.18** | текст в инпуте |
| `wf/x-small` | Inter Regular | **12** | 1.5 | лейблы таб-бара |
| `wf/x-small bold` | Inter Medium | 12 | 1.5 | активный таб |
| `Default/Bold/Body` | SF Pro Text Semibold | 17 | 22px | системный status bar |

**Рамп фактически из трёх ступеней: 32 / 18 / 16 / 12.** Между 32 и 18 нет промежуточных H1/H2 → на контентных экранах иерархия проседает. Тот же 16-Regular существует в двух line-height (1.5 и 1.18). Лейбл инпута прибит к переменной `--font/font-family/h1`, хотя это 18px-подпись → семантический рассинхрон имени.

## 7. Вывод: чему у кита учиться, а что не тащить в Decode

**Взять на вооружение:**
- **Единая высота контролов 60px** — чистый вертикальный ритм, без разнобоя. У нас tap-min 44; для hi-fi можно поднять базовую высоту полей/кнопок до 52–56 ради того же спокойного ритма.
- **Боковые поля 16px** — совпадает с нашим `screen-padding`.
- Полная токенизация (никакого хардкода) — то, к чему мы и сами идём.

**НЕ повторять (это анти-паттерны для нашей DS):**
1. **Две параллельные шкалы спейсинга** (`indent/*` + `blocks/inside/*`) с конфликтом имён (`xs`=8 vs 16). У Decode — одна шкала (4/8/12/16/20/24/32/48), одно имя = одно значение.
2. **Смешанные семейства радиусов** (`round/*` + `rounding/*`, 15 vs 16, 5px из спейсинга). У нас — одна лестница радиусов 8/12/16/20.
3. **Off-grid значения** (5px, 80px) — ломают 4/8-базу.
4. **Тонкий тайп-рамп** (провал между 32 и 18). Наш рамп плотнее: 12/13/17/20/26/34.
5. **Дубли line-height** на одном размере — у нас line-height привязан к стилю однозначно.

### Сверка шкал (кит → Decode)

| | example3 | Decode DS |
|---|---|---|
| Спейсинг | 5·8·16·24·32·48·80 в двух шкалах | 4·8·12·16·20·24·32·48, одна шкала |
| Screen padding | 16 | 16 |
| Радиусы | 4·5·12·15·16 (2 семейства) | 8·12·16·20 (одно) |
| Тайп-рамп | 12·16·18·32 | 12·13·17·20·26·34 |
| Тач-таргет | 60 (факт. высота) | 44 (мин.), контролы 52–56 |
| Шрифт | Inter (+SF Pro в status bar) | Inter (стенд-ин SF Pro) |

**Итог:** у кита сильный ритм по высоте контролов и правильный принцип «всё через переменные», но система токенов замусорена дублирующими семействами (2× спейсинг, 2× радиусы, 2× толщина штриха) и off-grid значениями. Decode’овская 3-tier система с одной шкалой на каждое свойство — чище и предсказуемее; из кита осмысленно перенять только идею единой высоты контролов и подтвердить боковые поля 16.
